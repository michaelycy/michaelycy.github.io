Sketch 设计稿怎样映射到已有组件

发布于 2020年6月19日

设计稿上有一个蓝底白字的「保存」。把它还原成矩形和文字，截图可能已经很像。代码交到业务团队手里，他们更希望直接用现有组件库里的主按钮，这样禁用态、键盘焦点和主题切换都有现成的实现。两种输出在设计稿的正常状态下看起来一样，下一次需求变更时，维护成本就分开了。

我参与过一套从 Sketch 提取设计信息、转换为组件代码或配置的工具。解析层把关键数据整理成 AST 或 JSON，中间用一层描述组件的 DSL 对接前端组件库。如果设计师只改了「保存」两个字，这一层能帮接手的人找到该动的是哪一个属性。

先决定这个图层组合代表什么

Sketch 文件里能读到页面、图层和共享样式等信息。页面可以分别解析，共享样式和页面引用则需要放在文档范围内理解。Sketch 文件格式说明

以「保存」按钮为例，解析阶段可以保留文本、尺寸、样式引用和来源图层。到了组件映射这一步，如果团队的设计规范已把某个 Symbol 对应到主按钮，就可以沿这条关系生成组件属性。仅凭蓝色矩形和一段白字来猜，会遇到长得很像的标签、链接和装饰元素。对于无法判定的组合，留下页面和图层位置，设计或前端就能回到原稿补一次映射。

为说明中间描述的作用，可以设想把这个按钮记为 Button(variant=primary, text=保存)。业务页面最终使用什么导入路径、属性叫 variant 还是 type，交给输出层适配。以后组件库调整接口时，可以拿现成的中间描述重新生成，查出这次变化落在设计含义还是输出规则上。

改一个按钮的字，再改两页共用的主色

假设第一页的按钮改叫「保存草稿」，第二页同款按钮仍叫「保存」。只改了第一页的文字，两页引用的共享主色没有动。如果下一次设计师改的是共享主色，第二页即使一个图层没动，按钮的颜色也得跟着变。只看页面文件的修改时间，容易漏掉这次变化。

项目对大文件用过多线程和增量解析。用这两页做例子，即使各页分到不同线程处理，合并时也要认得它们引用的是同一个共享样式。验证增量结果时，可以用同一份设计稿做一次全量生成作对照。

先改文字，看生成差异是否只落在第一页按钮的文本属性。再换共享主色，打开两页核对各自的按钮。如果输出引用了主题变量，这一次两页的组件代码可能都没有差异。只要主题定义已更新、两个主按钮都呈现了新颜色，这次改动就到了该到的地方。
